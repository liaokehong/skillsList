# product-design — 想法 → 多角色 PRD

把一个模糊的产品想法变成一份 PRD，四个下游角色拿到各自的部分就能开工：UI/交互能开始画、开发能排期、测试能写用例、管理能判断做不做。

PRD 没人能用的常见原因：所有内容混在一起写给"所有人"，结果每个角色都要自己再翻译一遍。本 skill 的核心原则是**按下游角色分区**，每个分区自足。

## 第 0 步 · 分诊

| 输入情况 | 走法 |
|---|---|
| 想法模糊到关键名词无法定义（说不清给谁用、解决什么） | 先做需求对齐（用 clarify-first skill；没有则至少产出关键假设清单），回来再继续 |
| 有基本方向的产品/功能想法 | 走下面的完整流程（主场景） |
| 只要单一文档（竞品分析、调研报告） | 跳过流程直接产出该文档，不套 PRD 模板 |
| 需求已明确的界面/交互设计执行 | 不适用本 skill |

## 流程

骨架取 Double Diamond 的前两阶段：Discover 发散理解 → Define 收敛定义。

### 1. Discover · 理解问题（别急着谈功能）

- **目标用户与场景**：谁、在什么情境下、遇到什么问题、现在怎么凑合、为什么不满。
- 用 JTBD 句式锚定：`当 <情境> 时，我想 <动机>，以便 <收益>`。
- 追问纪律沿用 clarify-first：**≤3 个**，只问"不问就会走偏"的。优先问三个方向：给谁用、核心痛点是哪个、成功怎么算。其余写进假设。
- 可选快速竞品扫描：只看同类产品怎么解决核心问题，不展开成完整报告。

### 2. Define · 定义方案

- **一句话产品定义**：给 <用户>，解决 <问题>，成功标准是 <可量化指标>。
- **功能拆解**：从场景推导功能，每条功能对应一个用户故事。
- **MoSCoW 优先级**：Must（没有就不能上线）/ Should（重要但不阻塞）/ Could（锦上添花）/ Won't（明确本轮不做——必须写出来，防止范围蔓延）。
- **范围外声明**：第一版明确不做什么，和 Must 同等重要。

### 3. 组装 PRD

按下面的模板产出。四个分区各写各的，互不混装。

### 4. 完工对照

- [ ] 四分区自检：设计拿到 §2§4 能开始画？开发拿到 §3 能排期？测试拿到 §5 能写用例？管理拿到 §1 能拍板？
- [ ] 每条验收标准可独立判定 通过/不通过
- [ ] 假设与未核实项列在文末，供用户一次确认

## PRD 模板

| 分区 | 给谁 | 拿到就能干什么 |
|---|---|---|
| §1 定义 | 管理/评审 | 判断做不做 |
| §2 用户与场景、§4 页面与流程 | UI/交互设计 | 开始设计 |
| §3 功能需求 | 开发 | 排期开工 |
| §5 验收标准 | 测试 | 直接转用例 |
| §6 假设 | 所有人 | 一次性确认/纠正 |

```markdown
# PRD：<产品名>（v0.1 草案）

## §1 一句话定义
给 <目标用户>，解决 <核心问题>，成功标准是 <可量化指标>。
第一版不做：<范围外声明>

## §2 用户与场景
- 目标用户：<1~3 类画像，每类一句>
- 核心场景（JTBD）：当 <情境> 时，我想 <动机>，以便 <收益>
- 现状与痛点：<现在怎么凑合，为什么不满>

## §3 功能需求
| # | 功能 | 用户故事 | 优先级 | 约束/备注 |
|---|---|---|---|---|
| F1 | | 作为<谁>我想<做什么>以便<价值> | Must | |

## §4 页面与流程
- 页面清单：<每页一句话目的>
- 关键流程：<主流程步骤序列，编号>

## §5 验收标准
- [ ] AC1：<可判定的 通过/不通过 表述>
- [ ] AC2：…
- 边界与异常：<空态、并发、超时、权限等>

## §6 假设与未核实项
1. <默认成立的假设，标注"待确认">
2. <未核实的事实，标注"未核实"及来源计划>
```

## 端到端示例（压缩版）

**输入想法**："我想做个团队周报工作台，每周催周报烦死了"

**Discover**（1 问 + 2 假设）：

- 问（1/3）：收上来之后你要的是"自动汇总成团队周报"还是"看清谁没交"？【推荐：汇总——痛点是花时间整理，不是监督】
- 假设：团队规模 ≤20 人；周报已有固定模板。

**Define**：

- 定义：给 10~20 人团队的管理者，解决"催收+汇总周报每周约 2 小时"的问题，成功标准：汇总耗时 ≤10 分钟。
- Must：模板化填写提交 / 到期自动提醒 / 一键汇总生成团队周报；Should：未交名单；Could：周报归档检索；Won't：跨团队聚合、数据分析看板。

**PRD 产出**（节选，展示填法）：

- §3 首行：F1 | 模板化填写周报 | 作为成员，我想在固定模板里填周报，以便不用想格式 | Must | 模板由管理者配置
- §5 首条：AC1 管理者点击"汇总"后 10 秒内生成含全部已提交周报的团队周报 → 测试可直接转用例
- §6：假设"团队 ≤20 人"待确认；"现状耗时 2 小时/周"未核实（用户口述）
